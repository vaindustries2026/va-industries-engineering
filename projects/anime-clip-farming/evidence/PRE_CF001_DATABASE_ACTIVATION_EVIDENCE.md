### 3.3 What could and could not be tested live

- **Runtime denial on the live database cannot be exercised.** The runtime role has no password and cannot log in, which is the state the brief requires, and `postgres` cannot `SET ROLE` to it (its grant is ADMIN only). The live evidence for the denial is therefore that the live function is byte-identical (md5) to the function that passed the local denial tests on both PostgreSQL versions.
- **Live admin-path check.** One `DO` block run as `postgres` (`session_user = current_user = postgres`) inserted a fixture franchise and moved it `DRAFT → BLOCKED → READY → RETIRED`, which includes both HUMAN_ADMIN edges, then ended in an unconditional `RAISE EXCEPTION`, so the whole statement rolled back. All four steps succeeded for the admin identity. Afterwards every `cf` data table held 0 rows. No data was committed.

## 7. Findings for the Company Brain

| # | Finding | Handling |
|---|---|---|
| F-2 | The runtime role could make HUMAN_ADMIN transitions. | **Fixed** by 0002 (ADR-002). |
| **F-6** | **Dated titles cannot change status after DRAFT, for any role.** `cf.freeze_after_first_status` compares `to_jsonb(OLD)` with `to_jsonb(NEW)`. The stored generated column `anime_titles.era_decade` (computed from `start_year`) is not yet computed in `NEW` during a BEFORE trigger, so the two differ and the trigger raises `CF_IMMUTABLE_ROW`. The freeze trigger fires before the status guard (trigger names sort `…_freeze` before `…_guard_status`). Effects: (1) the human `HUMAN_ADMIN` edges on titles that have a `start_year` (`BLOCKED → READY`, `READY → RETIRED`) fail for admins too; (2) for those titles the runtime role is stopped by `CF_IMMUTABLE_ROW`, not by `CF_GOVERNANCE_DENIED`. The runtime role is still blocked, so F-2 stays closed. The defect is in the approved 0001 design and its tests did not reach it (S1-RUN-01 moves a title only out of DRAFT). Franchises and undated titles are not affected; the runtime's deterministic path (DRAFT → READY, DRAFT → BLOCKED) is not affected. Pinned by harness check K1. | **Not fixed**: outside this brief's scope ("do not weaken the state machine", "no other changes"). Proposed follow-up migration (needs a decision): make the freeze check ignore generated columns, for example by adding `era_decade` to the ignored columns of the `anime_titles` freeze trigger or by comparing only non-generated columns. It must come with a regression test for dated titles. Until then, dated titles that need a human status change would need that fix first. |
| F-7 | The Supabase advisor reports 4 WARN `function_search_path_mutable` findings for the four `cf` trigger functions (SECURITY INVOKER, no `SET search_path`). They are bodies copied unchanged from the accepted design. Practical exposure is low: `cf` is not exposed to the Data API, the runtime role has no CREATE privilege anywhere, and the function bodies name `cf` objects with schema qualification. | **Not changed**: pinning `search_path` on all four is a small separate migration and is the Company Brain's call. Reported, not silenced. |
| F-8 | `0002_…VERIFY.sql` reads `pg_authid` for `runtime_role_passwordless`. The local non-superuser `postgres` cannot, so the local harness runs it as the superuser; on Supabase the `postgres` role can (this run). The column is expected to turn false once the human sets the password; every other column must stay true. | Documented in the file header. |
